# Model integration boundary

Python integration exists: model predicts one-hop success probability for currently available, non-history next-hop candidates that leave a shortest continuation. Cost combines `1 - predicted_success` and modeled tail success; 0.08 margin can retain previous choice. No candidates triggers minimum-hop fallback. Packet history and hop limit guard loops.

A separate packet-level C++ integration exists under `simulation/inet/ml-routing/`: `ml/train_tree.py` trains a route-choice tree from synthetic controlled-route scenarios, exports `DecisionTreeModel.h`, and `MeshRoutingApp` invokes it at next-hop decision time. It does not modify AODV; AODV stays in the sibling baseline. The Python `delivery_tree.joblib` model remains separate. INET tests validate Python/C++ prediction parity and safety fallback; four live INET integration tests are defined but skipped when the toolchain is unavailable. Five-seed curated results are synthetic simulation evidence; no physical firmware or measurements exist.
